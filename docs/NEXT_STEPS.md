# Следующие шаги после интеграции

Состояние интеграции и выполненные проверки: [INTEGRATION](INTEGRATION.md).
Владельцы оставшихся задач: [TASKS](TASKS.md). Требования организаторов: [CASE](CASE.md).

## Что закрыто

- Обучение и ежедневный прогноз строят признаки из одинаковых срезов выпуска.
  Общий стек переиспользуется между турбинами, цели ограничены явной датой.
- Есть ретроспективная оценка пяти моделей ансамбля: отдельные периоды обучения,
  настройки и оценки, сохранённые прогнозы, метрики, происхождение и полнота строк.
  Оценочные модели обучаются только по 30.11.2025; финальные модели подачи — по 31.01.2026.
- Пропавший ветер проходит через валидацию и одну попытку baseline; при повторной
  невалидности граф сохраняет ошибку и не публикует результат.
- Отдельные каталоги прогонов, защита отчётов, руководство судьи и индекс экспериментов
  позволяют проверять проект без перезаписи результатов команды.
- Версии зависимостей закреплены; используется Python 3.12+. Итоговые команды и результаты
  пересборки моделей и прогноза записываются в INTEGRATION.
- Панель и PNG читают сохранённую ретроспективную оценку. UI показывает дату выпуска,
  отсечку обучения, lead 1/2, маску целей и метрики из CSV; модель повторно не вызывается.
  Добавлены проверки обновления файлов, некорректных данных, произвольных границ дат
  и неполного набора турбин. Описание — [DASHBOARD](DASHBOARD.md).
- Объединены `scripts.reproduce`, Linux workflow и Docker без обучения при сборке.
  Проверка использует сохранённые модели без сети, сверяет прогнозы и оценку,
  защищает канонические каталоги от записи. Описание — [REPRODUCIBILITY](REPRODUCIBILITY.md).
- В git-истории `4e6f7ce` сохранены 28 завершённых LLM-трасс: `mode=openai`, без fallback.
  Точный model ID не записан; эти отчёты относятся к прежнему комплекту моделей и прогнозов.

## Завершение проверки общей сборки

Ветки панели и релиза объединены. Общий `build_features` округляет признаки до 10 знаков,
чтобы устранить влияние различий вычислений macOS/Linux на пороги деревьев. Пересобираются
обе группы моделей, сохранённая оценка, февральские выпуски и manifest. Новый канонический
прогон выполняется с `--no-llm`: в локальной среде нет API-ключа, отчёты создаёт шаблон.

Осталось зафиксировать полный набор тестов общей версии, повторение 28 выпусков и
1344 turbine-hours на macOS и в Linux без сети, совпадение прогнозов и оценки при
допуске `1e-9`, неизменность канонических файлов и запуск панели. Числа и команды
приёмки публикуются в [INTEGRATION](INTEGRATION.md) после завершения прогонов.

## 1. Проверяемая доступность погоды к часу выпуска

Равенство обучающих и прогнозных признаков проверено. Сшивка Previous Runs с задержкой
публикации может включать сведения, появившиеся после конца дня D. В кэше нет меток
доступности. Выбрать час выпуска, найти архив с проверяемой исторической доступностью
либо отдельно проверить вариант со старыми day 2/day 3. Затем переобучить и сравнить
по тому же протоколу. Проверка провайдера и ограничения Single Runs описаны в
[FEATURE_AVAILABILITY](FEATURE_AVAILABILITY.md).

## 2. Калибровка P10–P90

Выделить период калибровки внутри доступного прошлого, зафиксировать способ расширения
интервалов и измерить покрытие вместе с шириной по турбинам и lead. Сравнивать с текущим
диапазоном на том же протоколе; не подбирать калибровку по целям, на которых затем
заявляется её качество. Измеренное покрытие и номинал 80% показывать отдельно.

## 3. Новый LLM-прогон владельцем ключа

После пересборки моделей нужен новый отчёт по новым прогнозам. Владелец ключа может
сначала повторить один день в отдельном каталоге:

```bash
python -m src.cli run-agent --start 2026-02-10 --end 2026-02-10 --output-dir runs/llm-check
```

Проверить в трассе `mode=openai`, `completed=true`, `fallback=false`; сохранить точный
model ID и проверить объяснения по CSV того же выпуска. Для нового полного LLM-комплекта
повторить весь диапазон в отдельном каталоге и сверить численные прогнозы. Старые тексты
из `4e6f7ce` остаются историческим подтверждением работы LLM. Текущий режим канонических
отчётов указан в INTEGRATION.

## Внешний блокер GitHub Actions

Workflow интегрирован, но hosted-задания не стартуют из-за блокировки биллинга организации.
Администратору нужно восстановить доступ к раннерам и повторить workflow. Локальные
проверки Linux и состояние GitHub Actions фиксируются раздельно; отсутствие CI-запуска
не считается успешной проверкой. Подробности — [REPRODUCIBILITY](REPRODUCIBILITY.md).

## Последующие исследования

Дополнительные временные модели и NWP-источники сравнивать на том же протоколе,
сохранять параметры и результаты; не объявлять улучшение до измерения.
Факта февраля 2026 у команды нет.
