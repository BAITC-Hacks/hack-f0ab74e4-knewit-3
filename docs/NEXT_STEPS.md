# Следующие шаги: проверяемое качество и понятная сдача

План от 23.09.2026 по аудиту версии `389dfbb`, изменениям команды до `d982ca0`
и текущему исправлению агента.
Основание — [официальный кейс](CASE.md), рекомендации преподавателя и проверка кода.
Цель: судья воспроизводит февральский прогноз, видит происхождение данных и понимает,
какие показатели подтверждены. Задачи ниже — будущая работа, кроме явно отмеченного результата.

## Что уже реализовано

- Архивные прогнозы Previous Runs API, почасовая очистка SCADA, аэродинамические признаки,
  ансамбль LightGBM, P10/P90, Docker и интерактивные графики Streamlit.
- Проверка калибровки NWP → ветер → мощность проведена; проверенный вариант уступил прямой
  модели. Нейросетевая временная модель пока не обучалась и непосредственно не сравнивалась.
- **В текущем исправлении:** общий `DayGraph` для LLM и `--no-llm`, запись переходов и ошибок,
  продолжение того же состояния при отказе LLM; один переход на уже рассчитанный физический
  baseline при неудачной валидации. Повторная ошибка останавливает публикацию. Более поздняя
  погода для такого восстановления не загружается.
- Подача содержит 1344 строки. Правильный диапазон выпусков — **31.01–27.02.2026: 28 запусков,
  56 CSV турбин, 28 отчётов и 28 трасс**. Независимый верификатор текущей подачи проходит.

Владельцы: **данные/ML** — погодные срезы, признаки, обучение и оценка;
**агент/UI** — граф, провайдер, панель; **документация/релиз** — описание, среда и сдача.
LLM остаётся GPT-6 Luna. Для выполнения плана новый фреймворк оркестрации не нужен.
