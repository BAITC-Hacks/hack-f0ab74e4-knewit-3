# Следующие шаги после интеграции

Состояние интеграции и выполненные проверки: [INTEGRATION](INTEGRATION.md).
Точные владельцы файлов: [TASKS](TASKS.md). Требования организаторов: [CASE](CASE.md).

## Что закрыто

- Обучение и ежедневный прогноз строят признаки из одинаковых срезов выпуска.
  Общий стек переиспользуется между турбинами, цели ограничены явной датой.
- Есть ретроспективная оценка пяти моделей ансамбля: отдельные периоды обучения,
  настройки и оценки, сохранённые прогнозы, метрики, происхождение и полнота строк.
  Оценочные модели обучаются только по 30.11.2025; финальные модели подачи — по 31.01.2026.
- Пропавший ветер проходит через валидацию и одну попытку baseline; при повторной
  невалидности граф сохраняет ошибку и не публикует результат.
- Отдельные каталоги прогонов, защита отчётов, руководство судьи и индекс экспериментов
  позволяют проверять проект без перезаписи результатов команды.
- Версии зависимостей закреплены; используется Python 3.12+. Итоговые команды и результаты
  пересборки моделей и прогноза записываются в INTEGRATION.

## 1. Панель сохранённой оценки — следующая задача Agent 1

Ветка `dev/evaluation-dashboard`. Заменить историческую иллюстрацию финальной модели
в панели и PNG на прогнозы из `models_artifacts/evaluation/evaluation_predictions.csv`.
Рядом показывать период оценки, отсечку обучения, lead 1/2, фильтр чистых/всех наблюдаемых
целей и фактическое покрытие P10–P90. Источник чисел — сохранённый CSV и JSON-отчёт.
Это ретроспективная оценка: декабрь–январь ранее влияли на исследовательские решения.

Проверить обе турбины, границы дат, пустые/неполные результаты и отсутствие повторного
обучения при открытии панели. Сохранённую трассу подписывать как сохранённую.
Запуск и обновление графа вживую — дополнительный объём только после основной задачи;
повторный клик не должен запускать второй расчёт или перезаписывать канонические файлы.

## 2. Репетиция релиза в Linux — следующая задача Agent 2

Ветка `dev/release-rehearsal`. Подготовить одну команду воспроизведения, которая проверяет
среду, тесты, полный февральский прогон и целостность подачи в отдельном каталоге.
Добавить CI и выполнить контейнерный расчёт с отключённой сетью после установки зависимостей.
Сохранённые данные, модели и результаты команды должны остаться неизменными.

Приёмка: чистый клон, сборка образа Python 3.12, 28 выпусков, 1344 turbine-hours,
совпадение с подачей в пределах явно указанного допуска и доступная Streamlit-панель.
Локальная интеграция не подтверждает Docker: в её среде Docker отсутствовал.

## 3. Проверка LLM с действующим ключом

У владельца ключа выполнить один день в отдельном каталоге:

```bash
python -m src.cli run-agent --start 2026-02-10 --end 2026-02-10 --output-dir runs/llm-check
```

Проверить в трассе `mode=openai`, `completed=true`, `fallback=false`. Без ключа запускается
шаблон. После изменения модели старые LLM-тексты нельзя выдавать за анализ нового прогноза:
они сохранены в git-истории, текущий режим канонических отчётов указан в INTEGRATION.

## 4. Открытый вопрос времени публикации погоды

Равенство обучающих и прогнозных признаков проверено. Доступность всех погодных значений
к фиксированному часу выпуска пока не доказана: Previous Runs не сохраняет время публикации.
Выбрать час выпуска, проверить архив конкретных прогонов и доступность источников за весь
период, затем сравнить результат по тому же протоколу. Ограничения исторического покрытия
Single Runs описаны в [FEATURE_AVAILABILITY](FEATURE_AVAILABILITY.md).

## Последующие исследования

Калибровка интервалов, дополнительные временные модели и NWP-источники имеют смысл
после воспроизводимой оценки. Сравнивать на том же протоколе, сохранять параметры и
результаты; не объявлять улучшение до измерения. Факта февраля 2026 у команды нет.
