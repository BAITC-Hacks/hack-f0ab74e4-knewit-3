<a id="adr-001"></a>
## ADR-001 — Источник погоды: Open-Meteo Previous Runs API

**Действующее решение.** Обучение и инференс используют архивные прогнозы из
`previous-runs-api.open-meteo.com` (`*_previous_day1` / `*_previous_day2`).
Код: [`src/weather/openmeteo.py`](../src/weather/openmeteo.py). Погодная точка одна:
турбины находятся примерно в 300 м друг от друга. Сохранённый рабочий кэш начинается
с **01.03.2024**; эту дату использует `TRAIN_START`.

**История уточнения.** Изначально планировались обучающие признаки и резервный источник
из `historical-forecast-api.open-meteo.com`, а начало архива указывалось как январь 2024.
Этот путь не реализован; Historical Forecast не используется при запуске.
Доступность признаков конкретного выпуска требует отдельной проверки по [ADR-011](#adr-011).

**Почему.** Previous Runs предоставляет архивные прогнозные поля с нужными сдвигами
по дням; ответы сохранены в репозитории и повторно читаются без сети. Это выбранный
источник проекта, без утверждения, что иных бесплатных архивов не существует.

**Отклонено для входа инференса.** Измеренная погода и ERA5/реанализ: по
[ТЗ](CASE.md) нужны прогнозы, доступные на момент выпуска. Измерения допустимы как
цели обучения и для отдельно обозначенной диагностики.

<a id="adr-002"></a>
## ADR-002 — Модель: LightGBM поверх прогнозных признаков + физический baseline

**Действующее решение.** Отдельная модель на турбину получает архивную прогнозную
погоду. Baseline — обучаемая монотонная кривая `IsotonicRegression` по средней скорости
ветра ансамбля (`ens_ws_mean`). Первоначальное описание параметрической кривой устарело.
Финальный артефакт содержит пять LightGBM-моделей с разными seed, изотоническую кривую
и квантильные модели P10/P90. Код: [`train.py`](../src/models/train.py),
[`predict.py`](../src/models/predict.py).

**Историческая настройка.** Обучение предварительной одиночной модели — март 2024 →
ноябрь 2025; декабрь 2025 → январь 2026 использованы для ранней остановки, выбора
источников и веса бленда. В сохранённом отчёте вес LightGBM равен 1.0 у обеих турбин:
baseline доступен для сравнения и восстановления, но его вклад в обычный прогноз равен нулю.
После настройки пять моделей обучены на доступной истории до конца января.
MAE **0.1650 / 0.1661** относятся к предварительной одиночной модели на периоде настройки;
они не измеряют качество переобученного ансамбля. Подробнее — [ADR-011](#adr-011).

**Почему.** Бустинг обрабатывает табличные погодные признаки и пропуски, обучается на CPU.
Обучение на прогнозных полях позволяет учитывать их ошибки совместно с зависимостью
мощности от ветра; равенство срезов обучения и инференса теперь проверяется тестами.

**Не выбрано.** LLM как численный регрессор; обучение основной модели на измеренном ветре,
которого нет при выпуске. LSTM/TFT и другие нейросетевые временные модели **не обучались
и непосредственно не сравнивались**; их возможный выигрыш остаётся открытым вопросом.

<a id="adr-003"></a>
## ADR-003 — Агент: LLM с Python-инструментами и режим --no-llm

**Статус.** Исторический выбор Claude через Anthropic API заменён [ADR-010](#adr-010).
Общий исполнитель обоих режимов описан в [ADR-009](#adr-009).

**Сохранённое решение.** LLM вызывает готовые инструменты получения погоды, подготовки
признаков, расчёта, проверки и записи результатов. Численный прогноз считает модель;
LLM управляет допустимыми действиями и составляет отчёт. `--no-llm` выполняет тот же
конвейер детерминированно и позволяет воспроизвести расчёт без API-ключа.

**Почему.** ТЗ требует агентного цикла с анализом результата и повторным расчётом.
Самостоятельные Python-инструменты позволяют проверять вычисления и переходы без LLM.

<a id="adr-004"></a>
## ADR-004 — NVIDIA-кредиты не используем для обучения

**Действующее решение.** Обучение LightGBM выполняется на CPU; GPU в конвейере не нужен.
Это выбор текущей реализации, без сравнительного замера CPU и GPU.

**Заменённая часть.** Первоначальное утверждение «основной LLM — Claude» заменено
[ADR-010](#adr-010). Адаптер поддерживает Anthropic и OpenAI-совместимые endpoints,
в том числе конфигурацию NVIDIA NIM; наличие адаптера не подтверждает запуск на каждом
провайдере. Для работы без ключей используется `--no-llm`.

<a id="adr-005"></a>
## ADR-005 — Датасет коммитим в репозиторий

**Решение.** `data/raw/turbine_{1,2}.csv` — переименованные копии выданных файлов.
Погодный кэш также хранится в репозитории, включая данные отвергнутых экспериментов.

**Почему.** Судьи должны воспроизвести обучение из README; данные выданы для этого кейса.
Сохранённый кэш позволяет повторять расчёты без сетевых запросов и ограничений API.
Индекс используемых и экспериментальных кэшей — в [RESEARCH](RESEARCH.md#experiment-index).

<a id="adr-006"></a>
## ADR-006 — Время: всё в Asia/Almaty

**Решение.** Временные метки интерпретируются в `Asia/Almaty`; запросы к Open-Meteo
передают эту зону явно. В таблицах используются локальные datetime без tzinfo,
как в исходном датасете. Для февраля 2026 смещение — UTC+5.

**Почему.** Единая договорённость нужна для склейки целевых часов, погодного горизонта
и даты выпуска. Команда `python -m src.cli check-tz` проверяет корреляцию прогнозного
и измеренного ветра при сдвигах. Лучший лаг 0 — диагностический признак правильной
склейки, но сам по себе не доказывает доступность всех признаков на момент выпуска.

<a id="adr-007"></a>
## ADR-007 — Погодный вход: пять источников, без пространственных градиентов

**Решение.** Вход содержит `best_match`, `ecmwf_ifs025`, `gfs_seamless`, `icon_seamless`,
`ukmo_global_deterministic_10km`. Пространственные точки N/S/E/W исключены из основного
конвейера; `get_spatial_weather` и их кэш сохранены для воспроизведения эксперимента.

**Исторические результаты подбора, MAE T1/T2.** Четыре источника — **0.1666 / 0.1668**;
пять выбранных — **0.1650 / 0.1661**; с пространственными градиентами — **0.1658 / 0.1671**.
Сравнения проводились на декабре 2025 — январе 2026, уже использованном для настройки.
JMA (corr **0.541**) и CMA (**0.613**) не включены по результатам этой диагностики.

**Почему.** В проверенном варианте добавление пространственных признаков не улучшило
MAE. Оракул на измеренном ветре дал MAE **0.031** ([RESEARCH §3.1](RESEARCH.md#source-diagnostics)):
это указывает на существенное влияние ошибок погодного входа, но не доказывает, что
вся ошибка вызвана погодой или что улучшение модели невозможно.

**Не выбрано в проверенной конфигурации.** Пространственные градиенты, JMA и CMA.
Обобщение на другие периоды требует нового сравнения по [ADR-011](#adr-011).

<a id="adr-008"></a>
## ADR-008 — Прямая схема NWP → мощность, без ступени калибровки ветра

**Решение.** Оставляем прогнозные признаки → мощность. Проверенный вариант калибровки
NWP → ветер на площадке → мощность не выбран. Признаки недавней фактической выработки
в основной конвейер не входят.

**Исторический эксперимент.** В [`src/backtest/prof_ideas.py`](../src/backtest/prof_ideas.py)
вторая ступень учится на истории измерений с марта 2023, а прямая модель — на прогнозах
с марта 2024. Результаты на периоде настройки (12.2025–01.2026):

| Схема | Турбина 1 | Турбина 2 |
| --- | --- | --- |
| Прямая NWP → мощность | **0.1650** | **0.1661** |
| Двухступенчатая с калибровкой | 0.1653 | 0.1686 |
| + признаки недавней выработки | 0.1650 | 0.1645 |

Калибровочный регрессор дал MAE ветра **1.801** против **1.779 м/с** у среднего ансамбля
NWP. Возможное объяснение — потеря информации при сведении 108 погодных признаков
к одной оценке ветра. Замер не доказывает оптимальность среднего NWP и не исключает
других вариантов калибровки.

Недавняя выработка изменила MAE на **−0.0016** у одной турбины и на **0** у другой;
статистическая значимость не проверялась. Фактическая выработка заканчивается
31.01.2026, поэтому для последовательных февральских выпусков этот вход недоступен.
При наличии живой SCADA гипотезу можно проверить отдельно.

<a id="adr-009"></a>
## ADR-009 — Общий граф состояний без фреймворка оркестрации

**Решение, уточнено 23.09.2026.** LLM и `--no-llm` исполняют единый `DayGraph`
в [`src/agent/graph.py`](../src/agent/graph.py): контекст дня, проверка допустимого
следующего инструмента, сохранение трассы после каждого шага. Сбой LLM продолжает
тот же граф с текущего узла; повторно выполненные вычисления не нужны.

Неудачная валидация допускает одну замену ансамбля уже рассчитанным физическим
baseline и новую проверку. Погодный выпуск не меняется, более поздняя погода не
загружается; квантили ансамбля удаляются из резервного прогноза. Если baseline также
невалиден, день завершается ошибкой без публикации нового CSV. Причина восстановления
и отключения LLM видна в JSON и отчёте.

**Почему.** Общий исполнитель исключает обход валидации через вызовы LLM, сохраняет
одинаковую трассу обоих режимов и позволяет проверить переходы без внешнего API.
Baseline — аварийный вариант, без утверждения о повышении точности модели.

**Не выбрано.** Дополнительный фреймворк оркестрации для текущего небольшого графа.
Переходы покрыты сценарными тестами. В коммите `4e6f7ce` опубликованы 28 завершённых
трасс общего графа с `mode=openai`, без fallback. Автор коммита указал GPT-6 Luna;
точный идентификатор модели в самих трассах не сохраняется. См. [INTEGRATION](INTEGRATION.md).

<a id="adr-010"></a>
## ADR-010 — OpenAI GPT-6 Luna для LLM-оркестратора

**Решение.** LLM по умолчанию — `gpt-6-luna` через OpenAI Chat Completions.
Текущий адаптер передаёт `reasoning_effort=none` и `max_completion_tokens`.
Ключ берётся из `OPENAI_API_KEY` или `LLM_API_KEY`; Claude и NVIDIA NIM остаются
вариантами конфигурации. `--no-llm` сохраняет воспроизводимость без ключа.
Это заменяет выбор LLM в [ADR-003](#adr-003) и [ADR-004](#adr-004).

**Почему.** Агент вызывает готовые инструменты и составляет операторский отчёт.
При принятии решения использовалось сравнение тарифов: Luna — $0.10 / $0.50 за
1 млн входных / выходных токенов, GPT-4.1 Mini — $0.40 / $1.60. Это историческое
обоснование выбора, не текущая проверка цен и не измерение стоимости 28 запусков.
`python -m src.cli list-models` показывает доступные аккаунту имена; поддержку вызова
инструментов проверяет фактический запуск. Режим и завершение фиксируются в трассе.

Ссылки из исходного решения: [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna),
[GPT-4.1 Mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini),
[переход на GPT-6](https://developers.openai.com/api/docs/guides/latest-model).
В рамках очистки документации внешние тарифы и API повторно не проверялись.

<a id="adr-011"></a>
## ADR-011 — Происхождение признаков и статус оценки

**Статус.** Реализовано при интеграции PR #1 и #2. [Протокол оценки](EVALUATION.md),
[сохранённый отчёт](../models_artifacts/evaluation/evaluation_report.json) и
[журнал интеграции](INTEGRATION.md) фиксируют метод и результаты. Доступность NWP
к точному часу выпуска остаётся отдельно недоказанной.

**Решение.** Обучающие признаки и инференс должны строиться из одинакового среза
`get_issued_forecast(issue_date, weather)`, с явной связью даты выпуска, целевого часа
и `lead_day`. Лаги, опережения и центрированные окна ограничиваются этим срезом.
Изменение более позднего выпуска не должно менять признаки проверяемого выпуска.
Целевые данные финального обучения ограничиваются 31.01.2026.

**Причина.** В версии до исправления обучение строило окна по всему архиву с фиксированным
`lead_day`, а инференс — по отдельному выпуску. На границах суток и горизонта это может
давать разные признаки и брать поля другого выпуска. Использование только прогнозной
погоды само по себе не устраняет этот риск.

**Оценка.** Декабрь–январь уже участвовали в подборе. Повторная проверка на них должна
называться ретроспективной, с заранее зафиксированными временными границами и точной
конфигурацией ансамбля. Нужны сохранённые оценочные прогнозы, метрики по турбине и
горизонту, число наблюдений и маска простоев; отдельно — метрики на всех наблюдаемых
часах. Временные цели оценки не должны входить в обучение оцениваемой модели.

Независимая проверка на новом периоде остаётся предстоящей работой. Февральский факт
у команды отсутствует; корректный формат подачи и воспроизводимый запуск не являются
измерением точности на феврале.

После интеграции один стек признаков переиспользуется обеими турбинами; граница
канонических целей задана явно — 31.01.2026 23:00. Оценочный артефакт обучается по
30.11.2025 и применяется к выпускам не раньше этой даты: 5904 строки вместо исходных
5952. Оценка не допускает молчаливого исключения NaN-прогнозов. Недостающая погода
остаётся пропуском, а граф прекращает публикацию после неудачной резервной попытки.
