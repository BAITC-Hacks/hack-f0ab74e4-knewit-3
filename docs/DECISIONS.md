# Решения (ADR)

Формат: решение, почему, отклонённые альтернативы. Менять принятое — только новым ADR.

## ADR-001 — Источник погоды: Open-Meteo Previous Runs API

**Решение.** Архивные прогнозы берём из `previous-runs-api.open-meteo.com`
(`*_previous_day1`/`_previous_day2`), исторические прогнозные фичи для обучения — из
`historical-forecast-api.open-meteo.com`. Один запрос на точку (турбины в 300 м — одна точка погоды).

**Почему.** Единственный найденный бесплатный источник, отдающий именно «прогноз, каким он был
на момент выпуска» — прямое требование ТЗ. Ветер на высотах ступицы (80–120 м), архив с 01.2024.

**Отклонено.** ERA5/реанализ (нарушает ТЗ — это фактическая погода); платные архивы
(Meteomatics, DWD pay); парсинг сайтов прогнозов (нет архива).

## ADR-002 — Модель: LightGBM поверх прогнозных фич + физический baseline

**Решение.** Основная модель — LightGBM-регрессор на турбину, обучен на архивных прогнозных
фичах 2024-01→2026-01. Baseline — параметрическая кривая мощности. Финальный прогноз — бленд
(вес подбирается на holdout 12.2025–01.2026).

**Почему.** ~25k часов обучающих строк — территория бустинга, не нейросетей. Обучение секунды,
итераций много, риск нулевой. Обучение на прогнозной (не измеренной) погоде совмещает кривую
мощности и коррекцию ошибок прогноза в одной модели (RESEARCH.md §2).

**Отклонено.** LSTM/TFT (время, риск, нет выигрыша на этом объёме); обучение на измеренном
ветре (сдвиг распределений train/inference); LLM как регрессор (несерьёзно по точности).

## ADR-003 — Агент: цикл на Anthropic API с Python-тулами, плюс режим --no-llm

**Решение.** Оркестратор — Claude с тулами fetch_weather / prepare_features / run_model /
validate_forecast / analyze_report. Каждый тул — самостоятельная Python-функция. Флаг
`--no-llm` запускает тот же конвейер детерминированно.

**Почему.** ТЗ явно требует Agentic AI с полным циклом и «анализом результата, повторным
расчётом» — LLM здесь оправдан как слой анализа и принятия решений. `--no-llm` гарантирует
судьям воспроизводимость без нашего API-ключа (25 баллов за воспроизводимость).

**Отклонено.** Тяжёлые фреймворки (LangGraph, CrewAI) — время на изучение и отладку дороже,
чем свой цикл на 200 строк; n8n/no-code — не показывает техническую реализацию.

## ADR-004 — NVIDIA-кредиты не используем для обучения

**Решение.** Обучение на CPU. NVIDIA NIM опционально может заменить Anthropic API в агенте,
если у судей не будет ключа — но основной LLM это Claude.

**Почему.** LightGBM на 25k строк обучается секунды; GPU ничего не ускоряет. Экономим время.

## ADR-005 — Датасет коммитим в репозиторий

**Решение.** `data/raw/turbine_{1,2}.csv` лежат в репо (переименованные копии выданных файлов).

**Почему.** Судьи должны воспроизвести обучение из README (rule 5.4.15–5.4.16). Репозиторий
организаторский и закрытый, данные выданы для этого кейса. Кэш погоды тоже коммитим —
воспроизводимость без сети и без rate-limit.

## ADR-007 — Состав погодного входа: 5 источников, без пространственных градиентов

**Решение.** Финальный вход — best_match, ecmwf_ifs025, gfs_seamless, icon_seamless,
ukmo_global_deterministic_10km. Пространственные точки N/S/E/W (градиенты давления)
из фич исключены; модуль `get_spatial_weather` оставлен в коде.

**Почему.** Диагностика (RESEARCH.md §3.1): оракул на измеренном ветре даёт MAE 0.031 —
вся ошибка в прогнозе ветра, решает состав источников. Holdout: 4 источника — 0.1666/0.1668
(T1/T2), 5 сильных — 0.1650/0.1661, +пространственные градиенты — 0.1658/0.1671 (хуже).
JMA (corr 0.541) и CMA (0.613) ухудшали и исключены.

**Отклонено.** Градиенты давления как фичи (проверено — не дали выигрыша на 25-км сетке:
локальную орографию коридора глобальные модели не разрешают); JMA/CMA как источники.

## ADR-006 — Время: всё в Asia/Almaty

**Решение.** Внутренний стандарт времени — таймзона данных `Asia/Almaty` (UTC+5). Все запросы
к Open-Meteo с явным `timezone=Asia/Almaty`. Корректность склейки проверяет тест сдвига
корреляции (прогнозный ветер vs измеренный, лучший лаг должен быть 0).

**Почему.** Датасет в локальном времени без указания зоны; одна общая зона убирает класс
багов на 5 часов, ломающих точность молча.
