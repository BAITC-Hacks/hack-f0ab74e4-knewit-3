# Эксперименты, проверки и происхождение файлов

Производственный запуск использует `src/cli.py`, `src/agent/`, `src/weather/`,
`src/features/` и `src/models/`. Экспериментальные скрипты помогают проверить гипотезы;
их результаты нельзя автоматически приписывать финальной конфигурации модели.

## Команды и побочные эффекты

| Команда | Назначение | Результат / запись на диск |
| --- | --- | --- |
| `python -m scripts.verify_submission --directory forecasts` | Целостность CSV и выбор последнего выпуска | Сообщения и код завершения; файлы не меняет |
| `python -m scripts.compare_runs --a forecasts --b runs/check` | Разница чисел и характеристик текстовых отчётов | Сообщения; файлы не меняет; не измеряет точность |
| `python -m src.cli check-tz` | Корреляция прогнозного и измеренного ветра при сдвигах | Сообщения; может заполнить отсутствующий погодный кэш |
| `python -m src.backtest.experiments` | Сравнение основного входа с пространственными градиентами | Метрики в stdout; может заполнить погодный кэш |
| `python -m src.backtest.prof_ideas` | Двухступенчатая калибровка и признаки недавней мощности | Метрики в stdout; может заполнить погодный кэш |
| `python -m scripts.plot_holdout` | Иллюстрация финальной модели на январских обучающих датах | Перезаписывает `docs/img/holdout_week.png`; это не оценочный график |
| `python -m src.cli train` | Подбор и финальное обучение | Перезаписывает `models_artifacts/`; только для согласованного прогона |

Исследовательские скрипты используют декабрь–январь для ранней остановки и сравнений.
Их оценки — ретроспективные результаты настройки. Отдельная ветка Agent 2 добавит протокол
сохранённых оценочных прогнозов; до интеграции его команда не входит в обязательный запуск.

Чтобы сохранить лог эксперимента отдельно: создать `runs/experiments`, затем направить stdout
и stderr нужной команды в файл в этом каталоге. Записать SHA кода, версии пакетов и выбранные
источники рядом с логом. Не коммитить локальные модели и временные прогоны.

## Где искать исторические результаты

- `models_artifacts/train_report.json` — метрики подбора одиночной модели и выбранного бленда.
  В этом файле нет отдельной оценки точных пяти финальных моделей.
- [DECISIONS](DECISIONS.md#adr-007) — таблица выбора погодного входа;
  [ADR-008](DECISIONS.md#adr-008) — сравнение калибровки и признаков недавней мощности.
- [RESEARCH](RESEARCH.md) — ограничения экспериментов и направления продолжения.
- `forecasts/` — выход ежедневного процесса, не исследовательская метрика качества.

После изменения признаков или протокола прежние числа сохраняются как исторические.
Новый результат публикуется с командой воспроизведения и ссылкой на его артефакты.

## Погодный кэш: что используется

На базе `60f50bb` в `data/weather_cache/` — 76 JSON-файлов:

| Группа | Файлов | Назначение |
| --- | --- | --- |
| `best_match_*`, `ecmwf_ifs025_*`, `gfs_seamless_*`, `icon_seamless_*`, `ukmo_global_deterministic_10km_*` | 20 | Текущие пять источников в `src/config.py` |
| `sp_*` | 48 | Пространственные эксперименты в четырёх соседних точках |
| `jma_*`, `cma_*` | 8 | Материалы раннего сравнения источников; исключены из текущего конфига |

Эти файлы — сохранённые ответы API. Экспериментальные входы оставлены для воспроизводимости
отрицательных результатов; удалять их при уборке не нужно. Точный путь к запросу формируется
в `src/weather/openmeteo.py` из источника, периода и переменных. При новом запросе дополнительно
проверять координаты, единицы и временную доступность; имя файла не является доказательством
того, что все значения были доступны к конкретному часу выпуска.
