## Выполненная волна

| Ветка | Результат |
| --- | --- |
| `dev/forecast-availability` | Одинаковые признаки обучения и выпуска, происхождение строк, границы и пропуски архива, тесты и ограничения доступности |
| `dev/evaluation-protocol` | Ретроспективная оценка ансамбля, отдельные артефакты, CSV/JSON с периодами и метриками |
| `dev/judge-readiness` | Каталоги прогонов, защита отчётов, документация и уборка устаревших пояснений |

Интеграция добавляет общую отсечку обучающих целей, переиспользование стека признаков,
проверки пропавшего ветра, проверку полноты оценки и совместимую среду Python 3.12.
Команды пересборки и доказательства выполненных проверок находятся в INTEGRATION.

## Следующая параллельная волна

Каждый агент создаёт собственный worktree от обновлённого `origin/main` после интеграции.

| Исполнитель | Ветка | Файлы в его владении |
| --- | --- | --- |
| Agent 1 — панель оценки | `dev/evaluation-dashboard` | `app.py`, `tests/test_app_smoke.py`, `scripts/plot_holdout.py`, `docs/img/holdout_week.png`, новый `docs/DASHBOARD.md` |
| Agent 2 — репетиция релиза | `dev/release-rehearsal` | `Dockerfile`, `docker-compose.yml`, `.dockerignore`, новый `.github/workflows/reproducibility.yml`, `scripts/reproduce.py`, `tests/test_reproduce.py`, `docs/REPRODUCIBILITY.md` |
| Интегратор | отдельная интеграционная ветка | Общие документы, зависимости, разрешение конфликтов, итоговые артефакты и слияние в `main` |

- [ ] **Agent 1:** читать сохранённую оценку в UI и PNG; метрики совпадают с CSV;
  показать период, lead, число строк и фактическое покрытие интервалов.
- [ ] **Agent 2:** одна команда воспроизведения, Linux CI, контейнерный offline-прогон
  из чистого клона; зафиксировать результат, не менять результаты команды.
- [ ] **Владелец ключа:** реальный LLM-прогон одного дня на интегрированной версии.
- [ ] **Интегратор:** проверить оба handoff, объединить, повторить затронутые проверки
  и опубликовать согласованную версию обычным push.

`forecasts/`, `models_artifacts/`, `data/`, конфигурацию модели и обучение эти две задачи
не меняют. Необходимые изменения за пределами владения передаются интегратору.
Доказательство доступности погоды к часу выпуска остаётся отдельной задачей исследования,
а не критерием, который можно подтвердить исправлением подписей в интерфейсе.
