# Git-процесс на троих (контестный день)

Правила хакатона: история в организаторском репо, видимый результат каждый час,
версия в `main` на 18:00 — финальная. Отсюда процесс:

## Ветки

| Разработчик | Зона | Ветка |
| --- | --- | --- |
| Dev A | `src/weather/`, `src/features/` | `dev/weather` |
| Dev B | `src/models/`, `src/backtest/` | `dev/models` |
| Dev C | `src/agent/`, `src/cli.py`, README | `dev/agent` |

- Ветка живёт **не дольше часа**: сделал кусок → merge в `main` → ветку пересоздал от
  свежего `main`. Долгоживущие ветки на хакатоне = ад слияний и невидимый прогресс.
- Перед merge: `git fetch && git rebase origin/main`, прогнать свой модуль
  (`python -m src.cli train` или smoke своего куска), потом `git push origin main`
  (fast-forward merge локально или PR, если нужен ревью).
- Конфликты исключены границами модулей: **не редактируй чужие файлы**. Общие файлы
  (`config.py`, контракты в `ARCHITECTURE.md`) меняются только после слова в чате.

## Коммиты

- Сообщения на русском, по делу: что и зачем.
- **Никаких трейлеров про ИИ-инструменты** (`Co-Authored-By: Claude...` и т.п.) —
  проверь настройки своего Claude Code (`settings.json`: `includeCoAuthoredBy: false`).
- Каждый час в `main` должен быть коммит с работающим состоянием (правило 5.4.8–5.4.11).

## Если сломал main

Быстрый revert сломавшего коммита, потом чинить в ветке. Не чинить в `main` под давлением.

## После переписывания истории (уже случилось один раз)

История `main` была переписана (удаление трейлеров). Если у тебя старый клон:
`git fetch && git reset --hard origin/main` (свою незакоммиченную работу сначала в stash).
