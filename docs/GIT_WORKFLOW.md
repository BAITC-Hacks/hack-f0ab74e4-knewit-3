# Совместная работа и интеграция

Два внешних агента публикуют свои ветки, интегратор проверяет совместимость и объединяет
их в `main`. Точные файлы и задачи — [TASKS](TASKS.md), результаты первой волны —
[INTEGRATION](INTEGRATION.md).

## Каждый агент работает отдельно

После интеграции получить свежий `origin/main` и создать собственный worktree:

```bash
git fetch origin
git worktree add ../windcast-evaluation-dashboard -b dev/evaluation-dashboard origin/main
# Для второго агента — другая ветка и другой каталог:
git worktree add ../windcast-release-rehearsal -b dev/release-rehearsal origin/main
```

Каждый исполнитель выполняет только команду своей задачи. Если ветка или каталог уже
существуют, проверить их состояние и использовать существующую работу либо новое имя;
не удалять чужие изменения. Агент пушит только свою ветку. Запрещены force-push,
`reset --hard` и самостоятельное слияние в `main`.

Handoff содержит: ветку, полный SHA, базу, изменённые файлы/интерфейсы, команды проверок
с результатами, ограничения и команду воспроизведения. Локальный коммит ещё не является
опубликованной веткой. Коммиты описывают изменения на русском, без AI attribution trailers.

## Сгенерированные результаты

`forecasts/` и `models_artifacts/` обновляет один интегратор. Будущий оценочный режим панели
должен читать `models_artifacts/evaluation/`; оценочные модели обучены с более ранней отсечкой,
чем модели февральской подачи. Агенты сохраняют собственные результаты в `runs/<имя>`:

```bash
python -m src.cli run-agent --start 2026-01-31 --end 2026-02-27 \
  --no-llm --output-dir runs/check
python -m scripts.verify_submission --directory runs/check
python -m scripts.compare_runs --a forecasts --b runs/check
```

Каталог содержит CSV, отчёты, трассы и submission; сравнение соседних выпусков читает
тот же каталог. `runs/` игнорируется git. `compare_runs` показывает различия, но не
выбирает более точную модель и не является проверкой эквивалентности по коду выхода.

Без `--output-dir` используется `forecasts/`. В offline-режиме CLI защищает имеющиеся
LLM-отчёты; `--overwrite` явно разрешает их заменить. Отчёт, созданный другой моделью
или по старому прогнозу, нельзя сохранять как анализ нового результата.

## Общая сборка

1. Получить handoff, выполнить fetch и проверить SHA и границы изменений обеих веток.
2. В отдельной интеграционной ветке сохранить обе авторские истории и разрешить
   конфликты с учётом контрактов. Не выбирать одну сторону автоматически.
3. Выполнить весь набор тестов, проверить UI по сохранённому CSV и воспроизведение
   из чистой среды. Обновление моделей требует повторной оценки и новой подачи.
4. Проверить diff на секреты, временные файлы и случайные изменения канонических данных.
5. Получить свежий `origin/main`, включить новые командные коммиты и повторить затронутые
   проверки. Опубликовать интеграцию обычным push; при fetch-first повторить интеграцию.

Откат опубликованного изменения — отдельный revert-коммит с объяснением и сохранением
чужой работы. Проверенные команды и ограничения фиксируются в INTEGRATION.
