`dev/evaluation-dashboard` (`29cfbdf`), репетицию релиза `dev/release-rehearsal`

## Что исправлено при объединении

- Панель читает сохранённую оценку, показывает факт, baseline, lead и покрытие интервала.
  Обновление очищает кэш; повреждённые файлы сообщают ошибку. Дата по умолчанию остаётся
  внутри оценочного периода. PNG не перезаписывается при отсутствии одной турбины.
- Проверка релиза отклоняет пустой/неполный manifest, повторяющиеся оценочные ключи,
  неконечный допуск и частичный диапазон выпуска. `pytest | tee` в CI работает с `pipefail`.
  Проверка версии sklearn в Docker действительно превращает предупреждение в ошибку.
- Постоянная мощность, возможная при штиле или на плато кривой, вызывает предупреждение.
  Пропуски, неверная длина, отсутствующая турбина и выход за [0,1] по-прежнему блокируют выпуск.
- `build_features` округляет всю готовую матрицу до 10 десятичных знаков. Старые деревья
  разделяли математически равные признаки по младшим битам, зависящим от `libm`.
  Переобучены оба комплекта моделей, заново получены прогнозы, оценка и иллюстрации.
  Увеличенный допуск `0.05` удалён из CI и Compose; общий допуск составляет `1e-9`.

## Остающиеся ограничения

- GitHub Actions не получает раннер из-за блокировки биллинга организации. Локальные
  Linux-проверки выполнены, hosted CI требуется повторить после разблокировки.
- Декабрь–январь ранее влияли на исследовательские решения: оценка ретроспективная.
  Февральского факта у команды нет. Интервалы пока не откалиброваны к покрытию 80%.
- Previous Runs сшивает прогоны; в кэше нет времени публикации каждого значения.
  Доступность всего входа к фиксированному часу D не доказана. См. FEATURE_AVAILABILITY.
- CLI воспроизводит заданные даты. Планировщика и наблюдателя за обновлениями NWP нет.
