# Панель оператора: режимы и источники данных

`streamlit run app.py` — два режима, переключаются в боковой панели.

## Режим «Тестовый период (февраль 2026)»

Показывает канонические результаты rolling-прогонов из `forecasts/` (или каталога
из `--forecast-dir`): прогноз с интервалом P10–P90, погодный ансамбль выпуска,
граф выполнения агента с трассой и журнал решений. Факта за февраль у команды нет —
плитки это явно говорят. Незавершённый запуск (`completed: false` в трассе)
блокирует показ старых CSV этой даты.

## Режим «Ретроспективная оценка (есть факт)»

Читает **сохранённые** прогнозы протокола `retrospective-issue-replay-v1`
(см. `docs/EVALUATION.md`) из `models_artifacts/evaluation/`:
`evaluation_predictions.csv` + `evaluation_report.json`. Другой каталог —
`--evaluation-dir` или переменная окружения `WINDCAST_EVALUATION_DIR`
(используется тестами).

Ключевое свойство режима: **финальная модель не вызывается и ничего не
пересчитывается.** Панель показывает ровно те строки, что записал протокол —
прогнозы модели, обученной по 30.11.2025, для периода 01.12.2025–31.01.2026.
Прежний режим «историческая иллюстрация», который прогонял финальную модель по её
же обучающим датам, удалён: такой график показывал подгонку, а не качество.

Что показывается:

- **Сводка за период** — MAE/RMSE/MAE baseline и число строк по турбинам и
  горизонтам, пересчитанные из строк CSV (не из чисел в JSON) с переключателем
  «чистые цели / все наблюдаемые часы». Маска чистых целей — колонка
  `target_eligible`; отсутствующий факт остаётся отсутствующим и не заполняется.
  Измеренное покрытие P10–P90 подписано вместе с номиналом 80%.
- **Один выпуск подробно** — календарная дата плюс **явный выбор горизонта**
  (lead 1 или lead 2). Один целевой час существует в двух строках (из выпусков
  D-1 и D-2); панель никогда не усредняет их скрыто — выбранная пара
  дата+горизонт однозначно определяет один выпуск, и его дата показана плиткой.
  Первый день оценки не имеет строк lead 2 (их выпуск предшествовал бы отсечке
  обучения) — панель объясняет это, а не молчит.
- **График дня** — факт, прогноз ансамбля, физический baseline и интервал
  P10–P90 из строк CSV. Отсутствие интервала в строках подписывается явно.
- **Погодный overlay** — прогноз ветра строго из того же выпуска
  (`get_issued_forecast`); измеренная на турбине погода не подмешивается.

Ошибки данных (нет каталога, нет файлов, чужая схема, пустой CSV) дают понятное
сообщение с командой создания оценки — без падения и без тихого отката к
пересчёту финальной моделью.

Числа `train_report.json` в боковой панели остаются **метриками настройки**
(early stopping, вес бленда) и так и подписаны.

## Генератор PNG для README

```bash
python -m scripts.plot_holdout [--evaluation-dir models_artifacts/evaluation]
                               [--lead 1] [--start 2026-01-12] [--days 7]
```

Тоже читает сохранённый оценочный CSV (модель не пересчитывается). Каждый день
окна — отдельный выпуск; сегменты рисуются с разрывом на границах выпусков,
чтобы разные выпуски не сливались в одну непрерывную серию. Заголовок содержит
период, lead и отсечку обучения. Путь картинки прежний:
`docs/img/holdout_week.png` (ссылка из README сохраняется).

## Ограничения

- Это ретроспективная оценка, не нетронутый тест: декабрь–январь ранее влияли
  на выбор погодных источников и решений (подробнее в `docs/EVALUATION.md`).
- Трасса и журнал в февральском режиме — **сохранённые** артефакты запуска;
  живого управления агентом из панели нет.
