# Проверка проекта для судей

WindCast строит почасовой прогноз мощности двух турбин Шелекского коридора на 24–48 часов.
LightGBM рассчитывает мощность, общий граф проверяет порядок шагов и результат.
При включённом LLM он вызывает инструменты и пишет отчёт; без LLM это делает
детерминированный граф с шаблонным отчётом. Мощность 0.6 означает 60% номинала турбины.

## 1. Посмотреть готовую подачу

`forecasts/submission.csv` содержит 1344 строки: 2 турбины × 28 дней × 24 часа февраля 2026.
Дневные выпуски — 31.01–27.02; последний даёт 24 часа из-за границы архива.
Рядом лежат CSV по турбинам, отчёты и трассы. Проверка формата без ML-зависимостей:

```bash
python3 -m scripts.verify_submission
```

Ожидается `OK: 1344 turbine-hours`. Это проверка полноты, границ и выбора последнего выпуска.
Точность относительно февральского факта измеряют организаторы, у команды этих целей нет.
Новый комплект после пересборки моделей формируется с `--no-llm`: в локальной среде нет
API-ключа, отчёты создаёт шаблон. Режим каждого выпуска записан в его трассе.

28 прежних LLM-выпусков сохранены в git-истории в `4e6f7ce`: `mode=openai`,
`completed=true`, без fallback. Автор запуска указал GPT-6 Luna; точный model ID
не записан. Эти тексты относятся к прежним прогнозам, а не к пересобранному комплекту.

## 2. Воспроизвести в отдельном каталоге

Установка требует сети; затем погодные данные берутся из сохранённого кэша.
Использовать Python 3.12 и закреплённые версии из `requirements.txt`:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m pytest tests/ -q
python -m scripts.reproduce --output-dir runs/judge-check
```

Каталог должен отсутствовать или быть пустым. Команда блокирует сеть, проверяет manifest
и кэш, выполняет 28 выпусков сохранёнными моделями, проверяет подачу, пересчитывает метрики
оценки и повторяет оценочные прогнозы. Обучение и LLM не запускаются. SHA256 до и после
прогона проверяют, что канонические данные, модели и результаты не изменились.

`runs/judge-check` содержит CSV, отчёты, трассы, submission и `reproduction_report.json`.
Код 0 означает, что все проверки прошли; код 1 — расхождение, код 2 — недопустимый каталог.
Допуск по умолчанию — `1e-9`; его ослабление меняет условия проверки. Подробности —
[REPRODUCIBILITY](REPRODUCIBILITY.md). `compare_runs` остаётся диагностическим инструментом:
его код 0 сам по себе не доказывает совпадение. Подтверждённые результаты общей сборки
и среда проверки — [INTEGRATION](INTEGRATION.md).

## 3. Открыть панель

```bash
streamlit run app.py -- --forecast-dir runs/judge-check \
  --evaluation-dir models_artifacts/evaluation
```

Выбрать турбину и дату. Показать почасовую мощность, полосу P10–P90, прогнозы погодных источников,
отчёт и структурированный журнал. Кнопка обновления перечитывает файлы. Без аргумента панель
читает канонические `forecasts/`.

Панель показывает сохранённое выполнение; автоматической трансляции работающего агента нет.
Режим «Ретроспективная оценка (есть факт)» читает `evaluation_predictions.csv` и
`evaluation_report.json`. Выбрать турбину, целевую дату, lead 1/2 и чистые либо все
наблюдаемые часы. Метрики пересчитываются из выбранных строк CSV; дата выпуска и
отсечка обучения показаны отдельно. График содержит факт, ансамбль, baseline и P10–P90,
погодный срез берётся из того же выпуска. Модель при открытии панели не вызывается.

Отсутствующий факт и интервал остаются пропусками. Некорректные оценочные файлы дают
сообщение об ошибке, кнопка обновления перечитывает заменённые файлы. Измеренное покрытие
P10–P90 показано рядом с номиналом 80%; актуальное число берётся из сохранённой оценки.
Описание режимов и генератора PNG — [DASHBOARD](DASHBOARD.md).

## 4. Проверить LLM на одном дне

Добавить ключ в локальный `.env` по `.env.example`; файл не коммитится. Затем:

```bash
python -m src.cli run-agent --start 2026-02-10 --end 2026-02-10 --output-dir runs/llm-demo
streamlit run app.py -- --forecast-dir runs/llm-demo
```

В `trace_2026-02-10.json` проверить `mode`, `completed`, `fallback` и события. Для настоящего
LLM-прогона ожидается `mode=openai`, `completed=true`, `fallback=false`. Без ключа исполнится
шаблон; при сбое API граф продолжится с текущего шага и запишет причину. Один день создаёт
частичную подачу: требование 1344 строк относится к полному диапазону, а не к этому демо.

При неудачной валидации граф один раз применяет уже рассчитанную физическую кривую мощности
и проверяет результат повторно. Если резерв также невалиден, день не публикуется. Более поздняя
погода для восстановления не загружается; квантили ансамбля к резервной кривой не применяются.

## 5. Проверить качество и ограничения

- Обучение и ежедневный прогноз строят признаки из одинаковых срезов. Сшивка погодных
  прогонов с задержкой публикации может включать сведения, появившиеся после конца дня D.
  Время доступности отдельных значений в кэше отсутствует; подробности —
  [FEATURE_AVAILABILITY](FEATURE_AVAILABILITY.md).
- `models_artifacts/train_report.json` содержит метрики настройки. Отдельная ретроспективная
  оценка ансамбля находится в `models_artifacts/evaluation/`: CSV прогнозов и JSON с метриками,
  периодами, конфигурацией и полнотой. Оценочные модели обучены по 30.11.2025,
  модели февральской подачи — по 31.01.2026. Схема — [EVALUATION](EVALUATION.md).
- Декабрь–январь ранее влияли на исследовательские решения, поэтому оценка ретроспективная.
  Февральская точность неизвестна. P10–P90 нельзя называть калиброванным 80% интервалом
  только по названиям квантилей: сравнить нужно фактическое покрытие из отчёта.
- README и [ARCHITECTURE](ARCHITECTURE.md) объясняют устройство;
  [EXPERIMENTS](EXPERIMENTS.md) — команды и границы исследовательских результатов;
  [NEXT_STEPS](NEXT_STEPS.md) — оставшиеся задачи.

Повторить обучение оценочных моделей и replay отдельно от канонических файлов:

```bash
python -m src.backtest.evaluate --output-dir runs/evaluation-check
```

Dockerfile и Linux workflow объединены с панелью; образ использует сохранённые модели,
обучение при сборке не выполняется. Для общей версии выполняется пересборка моделей
с округлением признаков до 10 знаков, затем строгая проверка macOS/Linux с допуском `1e-9`.
Итог этой проверки ещё должен быть записан в INTEGRATION.

GitHub Actions пока не запускает задания из-за блокировки биллинга организации.
Это внешний блокер; локальная контейнерная проверка и состояние hosted CI отражаются
отдельно в [REPRODUCIBILITY](REPRODUCIBILITY.md).
