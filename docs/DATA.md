# Данные: профиль и правила обработки

Файлы: `data/raw/turbine_1.csv`, `data/raw/turbine_2.csv` (переименованы из выданных организаторами,
профилированы 23.09.2026).

## Структура

| Колонка | Описание |
| --- | --- |
| `ID` | порядковый номер строки |
| `Статистическое время` | локальное время, шаг 10 минут, формат `YYYY-MM-DD H:MM:SS` |
| `Средняя скорость ветра(m/s)` | измеренная на турбине |
| `Нормализованная активная мощность` | **целевая переменная**, 0–1 |
| `Средняя температура окружающей среды(°C)` | измеренная на турбине |

Диапазон: **2023-03-11 00:00 → 2026-01-31 23:50**, обе турбины.

## Правила обработки (обязательны для всех)

1. **Агрегация к часу:** прогноз почасовой → target = среднее нормализованной мощности за час.
   Час засчитываем, только если в нём ≥ 4 из 6 десятиминуток (иначе target = NaN, строка не идёт в обучение).
2. **Пропуски НЕ интерполируем в target.** Пропуск = вероятный простой/ремонт/обрыв связи.
   Интерполяция мощности внесёт фиктивные значения в обучение.
3. **Время в данных — локальное (Asia/Almaty, UTC+5).** Open-Meteo отдаёт UTC или по `timezone`.
   Все склейки данных — через явный `timezone="Asia/Almaty"` в запросах к API. Ошибка на 5 часов
   в склейке погоды с мощностью — худший тихий баг этого кейса, проверяется тестом на корреляцию
   прогнозного и измеренного ветра (сдвиг с максимумом корреляции должен быть 0).
4. **Ноль мощности при сильном ветре** (>4 м/с и power=0 длительно) — вероятный простой (curtailment
   / ремонт). Помечаем флагом, из обучения такие часы исключаем: модель должна учить физику ветра,
   а не расписание ремонтов, предсказать которые по погоде нельзя.
5. **Измеренные на турбине ветер и температура доступны только в истории.** На инференсе их нет —
   входом служит **прогноз погоды**. Поэтому обучаемся на прогнозных фичах (см. RESEARCH.md),
   измеренные значения используем только для контроля качества источника погоды.
6. Часовой ряд после агрегации: ~25 000 часов на турбину — достаточно для градиентного бустинга,
   мало для тяжёлых нейросетей. Это аргумент выбора модели (ADR-002).
